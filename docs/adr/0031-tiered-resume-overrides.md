# 挂起恢复改分级解除：用户导航意图可覆盖系统信号

ADR-0018 的"全部解除才恢复"存在可用性陷阱：系统内存压力挂起应用 A → 用户主动切回 A（路由条件解除）→ 压力未除 → A 不恢复 → 用户看到自己切到的页签是死的。决策：**来源分级**——路由（用户显式导航意图）> 系统信号 > 手动命令；高优先级来源的恢复意图可单独解除低优先级来源的挂起。但无脑恢复会让内存压力恶化，故恢复后该应用立即进入"**压力下候选驱逐**"名单——若压力持续，它是下一个 LRU 驱逐对象（交 ADR-0019/0026 的驱逐管线）。这是 ADR-0018"并集挂起、交集恢复"的修订：并集挂起不变，恢复改为分级解除。
