# 挂起消息队列：有界、按类型分级、溢出显式上报

挂起应用的消息队列若无限长，长期挂起的标签页会成为内存炸弹；若静默丢弃，"消息丢失"成了隐式行为。决策：每应用队列上限默认 1000；`state/changed` 类同键合并（last-write coalescing，保留最新值并标 `coalesced`）；普通消息 FIFO 丢最旧；溢出时向该应用投递 `bus/overflow` 控制消息。恢复时按每帧 50 条的微任务批次回放，避免长任务阻塞主线程。应用契约：**恢复后应把任何状态类数据视为可能陈旧，主动重拉**——"可能丢消息"是显式契约，不是隐式崩溃。

**注记（ADR-0023）**：本 ADR 的"状态类同键合并"仅适用于 **bus 通道**里的消息。state 通道（`ctx.on('state/changed')`）改走**拉模型**——挂起期间 state 服务不推送，恢复时按应用 watch 的键集合一次性同步当前值（`state/sync` 事件）。原因：状态可重拉、消息不可重放；且避免 state 反向依赖 lifecycle 的环。
